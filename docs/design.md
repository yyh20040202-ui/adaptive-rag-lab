# 设计与取舍

## 问题

这个项目同时处理两个问题：找回正确文献，以及让生成答案可以追溯到提供给模型的原文。向量检索不总能优于词项检索，格式正确的引用也不代表答案语义正确。因此检索质量、计算成本、引用有效性分别记录，不能用检索 Recall 替代问答正确率。

V1 保留轻量训练和预算路由作为成本基线；V2 增加真正的 token 级 cross-encoder，优先验证更强排序能否改善本机效果。新版实验以 [quality.json](../reports/quality.json) 的实测内容为准；报告产生前没有预设提升幅度。真实文献生成继续使用同一组六条固定声明，结果写入 [real_corpus_generation_v2.json](../reports/real_corpus_generation_v2.json)。

## 训练与负样本

正例来自官方train qrels；BM25 top-10中剔除该查询全部已知正例后采样一个难负例。batch由B个正例和B个难负例组成，查询对2B篇文档做温度0.05的对比分类；其他列中已知相关文档被屏蔽， designated positive保留。未标注相关性仍可能造成假负样本。

LoRA 只作用于 MiniLM 六层 attention 的 query/value，r=8、alpha=16，实际更新 73,728 个参数。底座冻结；训练 4 轮后依据文档分组验证集的固定对比损失选第 1 轮。第 0 轮也是候选，避免把微调本身当作保证提升。192-token 截断降低 CPU 开销，也可能丢失摘要末尾证据，限制写在模型卡。

## 召回、重排与路由

BM25使用CountVectorizer稀疏矩阵和Robertson式IDF；中文字符词项只供本地小语料使用。RRF深度100、constant60；float64防止同分的float32不对称舍入。

V1 的神经重排输入为池化向量的逐维乘积、绝对差、log-BM25、余弦相似度和词覆盖率，MLP 输出相关性分数。验证集 BCE 选权重，验证集 nDCG 选与 RRF 的混合比例 0.15。它没有 query/document 逐 token 联合 attention，不能称作 cross-encoder。原始测试结果保留在 [retrieval.json](../reports/retrieval.json)：完整轻量重排 nDCG@10=0.6925，BM25=0.6468。

V2 的 cross-encoder 将查询和候选文献**成对分词、联合编码**，通过 sequence-classification 相关性 logit 重排候选。查询与文档 token 可以在同一网络中交互，表达力强于池化后的 MLP，但每个查询需要重复编码多篇候选。它只重排候选集合，不能找回召回阶段完全遗漏的文献。MiniLM运行时仅对Linear层做CPU动态INT8量化，BGE采用Q8_0 GGUF Vulkan推理；实际量化流程参与验证/测试。它们不是QAT，也不假定FP32与量化的质量相同。

公开候选为MiniLM L6/L12与BAAI BGE v2-m3。MiniLM来自上游英语MS MARCO监督，下载固定revision的safetensors；BGE采用GPUStack转换的Q8_0 GGUF，固定revision、大小与SHA256，通过llama.cpp b11517 Vulkan推理。本项目未微调这些重排器。BGE上游支持多语种，但当前只验证英语SciFact；不能宣称中文知识库效果已被验证。

选择流程先以 LoRA hybrid 的 RRF 产生 100 条候选，再比较 L6/L12/BGE、重排深度 20/50/100、融合权重 α∈{0, 0.25, 0.5, 0.75, 1}。query/document 成对编码长度上限为 384 tokens；cross-encoder 原始 logit 与 RRF 分数分别做 min-max 归一化后加权融合。α=0 保留不使用 cross-encoder 分数的候选，防止把新增模型视作必然改善。三模型共45项配置。CPU动态INT8短batch的激活缩放会变化，20/50候选的尾部批次重新计算以匹配线上。BGE原始logit不当作校准概率。163 条分组验证查询的 nDCG@10 决定配置；精确同分优先更浅候选，再优先 L6。

验证网格和资源采样写入 [quality_selection.json](../reports/quality_selection.json)，选定配置冻结在 [quality_config.json](../checkpoints/quality_config.json)。之后只按该配置运行 300 条测试查询，保存逐查询结果与成对 bootstrap 差值区间。报告产生前不填写选中模型、测试提升或新版耗时。

router使用7个BM25可得特征，MLP输出BM25、LoRA hybrid或neural rerank。监督目标是训练查询的nDCG减代理计算成本；五个成本惩罚配置只在验证集上比较。模型训练后的in-sample质量可能让路由训练标签过于乐观，因此保留独立验证并建议后续做OOF标签与域外评测。代理cost不是实测latency，后者独立计时。

运行时路由先于查询编码，BM25路径不会先计算向量再假装节约成本。用户导入资料上的学习路由默认关闭，因为仅在SciFact验证过。

## 数据划分、缓存与新版比较

BEIR SciFact 有 5,183 篇文献，官方 train qrels 中的 809 条查询按相关文档连通分组拆成 646 条训练、163 条验证；300 条 BEIR 测试查询参与最终排名评估。检索语料共享，训练/验证的监督信息按分组隔离。这里的 BEIR test 来自原 SciFact 的有标注验证集，不是原任务隐藏测试榜单。

V1 测试结果已经被查看，V2 是对同一 300 条查询的迭代比较。新版配置在分组验证集上选择、测试标签不参与训练或选配置，但不能把重复使用的测试集称作全新、未观察过的最终检验。要判断改进能否泛化，还需新增领域、未使用过的外部集合和多个训练种子。基座与重排器的上游预训练污染情况未知，不能声称严格 zero-shot 或 SOTA。

新版向量缓存绑定按顺序排列的文档 ID 与文本、query 文本、基础模型/分词器文件、adapter 权重与配置，以及截断长度、向量维度、dtype 和池化版本。同一 ID 的正文被修改也必须重建索引，不能仅凭文件存在就复用旧向量。旧缓存缺少这些元数据时应拒绝加载并提示重建。分块工具默认 1,200 字符、重叠 150 字符，保留原文档 ID 和 `document.content` 的字符起止位置；片段位置用于追溯，不把片段 ID 当作另一篇独立论文。字符上限不保证一定装进 192/384-token 模型，尤其中文仍需注意分词截断。

## 本地生成和证据

从检索结果中选取和查询相关的原文窗口，保留 `document.content` 的字符偏移。先为后面的来源预留预算，再在余量内扩大上下文，避免第一篇长摘要挤掉后排文献的关键句。标题只作为来源元信息，不能单独被选作证明研究结论的引用。

V2 将窗口内的正文拆成最多 360 字符的**连续原文跨度**，给它们分配局部 `span_id`。模型看到的是来源标题和带 ID 的原文跨度，JSON 解码约束只允许选择已有的跨度 ID。客户端把选择映射成原有的 `{source_id, quote}`，随后仍由 `validate_answer` 检查来源 ID、逐字匹配和字符偏移。这样减少了小模型复制长英文引文时的格式错误，没有替它编造结论、重写原文或放松最终审计。

对实际送入模型的完整跨度 JSON 调用本地 Qwen tokenizer，预算包含 ID 与序列化开销，而不是只计正文字符。默认 1,400 evidence tokens、最多 384 输出 tokens、问题最多 1,000 字符；证据预算不包括系统提示、问题和输出，完整推理还需容纳在生成服务的上下文长度中。真实输入是 SciFact 声明时，提示要求判断证据支持、反驳或不足，并说明具体发现；不能只把声明复述成答案。

生成服务只接收 loopback HTTP 地址，`trust_env=False`，避免意外通过环境代理转发资料。回答/拒答具有两个互斥 JSON 分支：回答分支选择 1–2 条原文跨度，拒答分支没有答案和引用。来源错误、缺少引用、重复跨度、输出超限或模型格式错误均拒答；没有启动本地生成服务时明确报告不可用，不返回假模型答案。另用保守规则拦截无主题重合、问题复述和显式未知事实。

生成模型名称通过 `LLAMA_MODEL_LABEL` 配置并记录在结果中。Qwen GGUF 在这里仅做本地推理，没有进行 Qwen SFT/LoRA。升级到更大模型取决于下载、可用 RAM 和本机实测，不能把尚未运行的模型记作成果。

**合法引用不证明语义蕴含。** 即使模型只选真实原文跨度，仍可能选错证据、反转因果或给出不受引文支持的结论。因此 `real_corpus_generation_v2.json` 的 answered 数表示通过机械引用审计的输出数量，不能换算为 QA 准确率；检索 qrels 只标识相关文献，没有生成答案金标准。六条声明是固定诊断样例，V1 失败也保留。模拟制度样例仅用于格式/拒答回归，不参与主页面演示或对外宣称准确率。

## 笔记本运行约束

默认 `ADAPTIVE_CPU_THREADS=2`，显式设置最多保留 4 个 PyTorch CPU 线程；成对推理 batch 上限为 8。资源模块提供进程内串行锁，批量 cross-encoder 质量评估使用该锁；它不会自动协调多个 Python/llama.cpp 进程，因此本机执行时仍需串行启动重任务，避免训练、批量评估和大模型生成叠加占用。MiniLM排序模型使用CPU，BGE排序和Qwen生成可用llama.cpp Vulkan推理；本项目不安装CUDA训练环境。API中的检索与生成共享进程内重任务锁，跨语料的问答不会并行执行重模型。

每批向量编码或 cross-encoder 推理前检查可用系统内存：低于 `ADAPTIVE_MIN_AVAILABLE_GIB=2.0` 时停止计算；Python 进程 RSS 超过默认 `ADAPTIVE_MAX_PROCESS_GIB=3.0` 也停止。`ResourceRecorder` 保存采样时看到的最大进程 RSS、最低系统可用内存、采样次数和耗时。

这是**批前采样与安全停止规则**，不是操作系统强制内存限额，也不保证任何时间点绝不会出现资源峰值。其他应用、浏览器和生成进程仍可能改变剩余内存；本地生成服务器应单独限制并发、上下文与 GPU offload，并在资源不足时降级或停止。质量提升必须与这些真实资源记录一起阅读，不能只展示最好看的分数。

建议通过 `python -m adaptive_rag.launch_generator` 启动GGUF服务。默认GPU offload99、CPU2线程、context3072、batch256/ubatch128、单并发；每2秒检查系统可用RAM与自身生成子进程RSS。低于2GiB余量或子进程超过3GiB时只停止自己的子进程，Ctrl+C也按此规则收尾；不会终止其他应用。看门狗仍是采样防护，不是OS硬限额。

FastAPI默认仅监听127.0.0.1；文字导入20,000字，PDF最多2MiB/30页；本地资料只在进程内存，不写入仓库。当前代码不适合未经鉴权与隔离直接公开部署，未实现企业多租户权限、持久化或完整语义安全评估。

BGE是在本机量化GPU推理验证可行后加入候选；候选扩展与参数选择均早于V2测试。GPU重排服务使用512上下文、单并发；生成器默认使用3072上下文，二者由独立RAM看门狗管理。GPU/客户端/服务进程的资源记录范围分别标明。

两个GGUF服务都显式设置 `--cache-ram 0 --ctx-checkpoints 0`，避免旧提示状态长期累计。早期重复诊断触发过RAM余量守卫，事件、三条中断进度和诊断保存在 `reports/resource_incident.json`；该中断不是完成的六条评测。4B Instruct候选通过部分GPU offload为BGE保留显存，仍必须在实际硬件上复测。

SciFact问答另检查数字复合词与英文正式标识是否出现在证据中。缺失则保守拒答，同义表达可能被错拒；这不是语义蕴含分类器。支持标签后仅重复问题的回答也会被拒绝。生成提示要求两句以内描述具体发现，解码长度上限留余量，避免600字符语法硬上限在词中间结束而被误当完整句子。

`auto` 模式先检查选定模型文件和GGUF服务健康；服务被资源守卫停止后自动退至可用的轻量路径。显式指定cross-encoder的请求仍报告服务错误，不能悄悄换模型而把结果记成强模型输出。

4B初次GPU24层/mmap加载与BGE同时驻留时也触发余量守卫，未完成任何新诊断输出。最终在同一保护线下尝试GPU30层、3072上下文和直接权重加载（启动器--no-mmap对应b11517 --load-mode none）；加载后的余量和重复查询采样保留在runtime_verification.json。不能将其他硬件的内存收益视为保证。
