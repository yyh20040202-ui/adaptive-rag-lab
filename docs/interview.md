# 面试准备：把实现和证据讲清楚

## 90秒介绍

“我做的是文献证据驱动的本地 RAG 实验项目，用 BEIR SciFact 的 5,183 篇真实摘要，按相关文档连通分组拆出 646 条训练和 163 条验证查询。MiniLM 的 LoRA 只更新 73,728 个参数，使用 BM25 难负样本和已知假负例屏蔽。V1 的完整轻量重排把 300 条测试查询的 nDCG@10 从 0.6468 提高到 0.6925；预算路由减少向量调用但会损失质量，我保留了这个取舍。V2 增加 query/document 逐 token 联合编码的 cross-encoder，所有模型和融合配置只在验证集选择，再冻结后比较同一测试集。生成使用本地 Qwen，限制证据 token 预算，让模型选择原文跨度，再做引用和字符偏移核验。CPU 默认两线程、batch 上限八，并在可用内存不足 2 GiB 时停止重计算。项目保留真实失败，引用合法不等于答案正确。”

V2 的新结果只从 [quality.json](../reports/quality.json) 读取；报告未完成时不加入提升百分比。生成只展示 [real_corpus_generation_v2.json](../reports/real_corpus_generation_v2.json) 的原始输出，不把六个案例的通过数讲成问答准确率。简介中的“测试”应同时说明：V1 结果已经被看过，V2 使用的是同一测试集的迭代比较，不是全新的盲测。

## 必须能回答的追问

1. **LoRA更新了哪里？** MiniLM六层attention的query/value，r8/alpha16，73728参数；底座冻结。不是大语言模型SFT。
2. **为何用难负样本？** 随机负例往往过于容易，BM25近邻更接近检索实际误例；已知正例要剔除，还要处理batch中的假负例。不能发现所有未标注相关文档。
3. **怎么避免验证泄漏？** 引用同一相关文档的查询连通分组，监督不跨 train/val；检索语料共享。测试标签不参与负例采样、训练、选权重和配置。V2 在已观察过的 300 条测试查询上迭代，不能声称全新盲测；需要新增未使用集合验证泛化。
4. **Recall和nDCG差别？** 前者看找回相关文档的比例，后者对位置折扣、支持graded relevance。MRR关注首个相关文档位置。指标必须说清cutoff。
5. **两种重排有什么不同？** V1 的 MLP 输入已经池化的 `q*d`、`abs(q-d)` 和检索特征，没有逐 token 联合 attention。V2 的 MiniLM / BGE cross-encoder 成对分词 query/document，在同一网络中交互，输出相关性 logit；更强但每个候选都要重新编码。它只排序已有候选，召回遗漏仍然无法修复。
6. **路由真的节省计算吗？** 先提BM25特征再预测路径，轻路径不调用encoder；离线缓存的语料向量仍需预先建立。不要把减少调用等同于同比降低总能耗。
7. **路由为何掉质量？** 只看稀疏特征无法准确判断每条查询是否需要dense，训练cost目标有质量预算取舍；验证也更偏轻路径。保留完整流程供质量优先场景使用。
8. **置信区间证明什么？** 对300条查询成对重采样的delta区间；不能覆盖训练随机种子、分布漂移或基座污染。
9. **为何第1轮好于第4轮？** 训练损失下降但文档分组验证损失上升，小训练集可能过拟合；依据验证损失选权重并保留epoch0候选。
10. **引用跨度选择能消除幻觉吗？** 不能。模型从约束集合中选择 `span_id`，程序恢复精确 `{source_id, quote}` 并核对原文位置，解决了引文复制和来源伪造的机械问题。模型仍可能选真实但无关的句子，或者把因果关系说反，需要独立问答标注、语义蕴含和人工评估。标题不会被当作可选证明。有效引用比例不代表语义支持率。
11. **哪些模型训练过？** 本项目实际训练了 MiniLM LoRA adapter、轻量 ranker 和 router。V2 cross-encoder 使用上游 MS MARCO 预训练权重；本地 Qwen GGUF 只用于推理，没有 Qwen SFT/LoRA。实际生成模型型号以运行环境 `LLAMA_MODEL_LABEL` 和报告记录为准，不能把更大模型尚未完成的尝试讲成已实测成果。
12. **代码由谁开发？** 这是AI辅助的个人学习项目。面试前应能独立改动训练采样、模型加载、指标与服务流程，不声称独立完成全部代码或已在企业生产使用。
13. **V2 怎么选模型与参数？** 固定 LoRA hybrid 的 RRF depth=100、constant=60；比较 L6/L12/BGE，重排 20/50/100 篇候选，α 为 0/0.25/0.5/0.75/1。384-token成对输入；MiniLM采用CPU动态INT8 Linear，BGE采用Q8_0 GGUF Vulkan推理，实际量化模型参加验证和测试；不是QAT，未声称与FP32效果相同。归一化 cross-encoder logit 与 RRF 分数后融合。163 条分组验证查询的 nDCG@10 选配置；同分优先更浅候选、L6。读取 `quality_selection.json` 和 `checkpoints/quality_config.json` 说明实际选中项，不凭测试表现改参数。
14. **小电脑如何运行更强模型？** 优先提升候选排序，不盲目加训练轮数。默认 CPU 两线程、编码/成对推理 batch 上限八；每批检查系统可用内存，低于 2 GiB 或进程 RSS 超过 3 GiB 即停止。重任务串行启动；`launch_generator` 对自己启动的GGUF子进程使用单并发、3072上下文和2秒RAM看门狗。它只停止自己的子进程；批前/周期采样都不是 OS 硬限额，不能保证其他应用不造成资源峰值。
15. **证据 token 预算包含什么？** 包含实际送入生成模型的原文跨度 JSON、来源元信息、跨度 ID 和序列化开销，通过本地模型 tokenizer 计数。系统提示、用户问题和输出另占上下文。多来源先分配份额，再扩展剩余预算，避免第一篇长摘要挤掉后面的证据；缺少可引用正文时拒答。
16. **同一个文档 ID 改了内容，旧索引还有效吗？** 无效。新版缓存指纹包含有序文档 ID/文本、query 文本、基础模型与 tokenizer 文件、adapter 权重/配置、截断长度、向量维度和池化版本。缓存缺少指纹或不匹配时必须重建，不能只核对 ID 和 adapter 文件。
17. **“六条里回答更多了”证明什么？** 最多说明该固定诊断集上通过机械引用审计的输出增加。没有生成答案金标准，也不是新的独立评测；原 qrels 是检索相关标签，不能拿来计算 QA accuracy。应逐条人工检查结论是否被引文支持，并说明模型拒答、检索缺证据和格式错误各占多少。

## 下一轮有意义的实验

- 至少3个训练种子，记录效果均值、方差与CPU耗时。
- 对比无hard negative、不同LoRA rank、不同截断长度；所有配置仍只在验证集选。
- 以OOF检索质量生成router标签，测不同质量预算的Pareto曲线。
- 增加公开中文/跨领域检索集，重新校准路由；不能直接拿SciFact数字写成中文企业收益。
- V2 已比较MiniLM与BGE候选，下一步应在更多公开集合评估，而不是继续对同一测试集挑模型；保留 V1 MLP 与 BM25 作为成本基线，不以模型大小替代测量。
- 收集独立问答金标准，评估语义支持率、错误拒答、缺证据拒答与提示注入；12个调试用例不能充当独立QA分数。
- 增加从未用于当前调试的新测试集合，对配置完全冻结后再运行，区分迭代比较和外部验证。

## 阅读顺序

先看 `reports/analysis.md`、训练日志、`quality_selection.json`、`quality.json` 和两版真实生成记录，再读 `data.py → train.py → retrieval.py → ranking.py → cross_encoder.py → quality.py → engine.py → evidence.py → generator.py`。资源限制看 `resources.py`，GGUF协议看 `reranker_client.py`，缓存一致性看 `cache.py`。亲手修改一个参数、只在验证集重跑小实验并解释结果，才能将仓库变成自己的面试材料。

18. **为什么关闭提示缓存？** b11517默认RAM提示缓存预算较大，初次重复请求时观察到生成进程RSS增长，并触发2GiB余量守卫。两个服务显式设置cache-ram=0和ctx-checkpoints=0，再重复相同诊断并记录资源。守卫只停止自己启动的进程，不能终止其他应用来凑内存。
19. **更换生成器是否证明准确率提高？** 同一六条声明用于失败诊断，早期1.7B曾混淆TET肿瘤背景和HMGB1触发条件，引用逐字匹配仍未保证结论正确。更换模型和短回答提示后保留每版输出；没有独立QA标签，不能把更多非拒答写成准确率提升。逐条复查见generation_review.md。
